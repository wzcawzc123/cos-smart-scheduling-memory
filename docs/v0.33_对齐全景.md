> 2026-10-12 · UnifiedRootOptimizer · 依据：runtime 源码逐层核对 + 2026-10-11 真机实探
> 用途：回答"实现是否偏离架构图"，并给出**未启用槽位清单**作为后续施工索引。

## 0. 结论（一句话）

**没有偏离。** 三张图（架构定案 §0 运行闭环 / 设计文档 §3 六层 / README 三执行器）
与代码逐层对应；问题是**有一半槽位是空的或开关是关的**，不是图纸错了。

设计文档 v1.1 §1.1 本就写明：「第一目标设备为一加11（SM8550/COS16/KSU 3.3.0），
**0.x 阶段不追求多设备通用性**；通用性由 Capability Adapter 预留，由 Phase E 兑现」——
所以"单机特调"是原定定位，不是转向。

## 3. 热控现状（三条链路，以代码为准）

```
① 观测：drivers.cpp thermal 事件（ThermalChanged）
        + evidence.cpp 每 60s → thermal.jsonl（top3 热点 + battery，只读）
        + 热级计算 next_thermal_level(prev, temp, T1, T2, hyst=8, trend)
        + 参数来源：uro.conf 的 THERMAL_ENABLE / THERMAL_T1（默认78）/ THERMAL_T2（默认85）
② 决策：PolicyManager → thermalCapped 标记 + 档位回退
        （超 T1 → 压回 BALANCE；超 T2 → 仍 BALANCE，不叠省电，避免与 thermal-engine 重复惩罚）
        + dwell 3min 只升不降（v0.31 防震荡）
③ 执行：无独立执行器 —— 回退通过 Controller 应用"档位对应的参数"实现
```

与设计文档 §5.4（T-INT 应"通过 Constraint Engine 输出 CPU/GPU max clamp"）的差异：
当前是**档位回退**，不是 clamp 输出。二者都能降温，但后者更精细（可按温度连续调）。
若要改成 clamp 路线，落点 = `ThermalPlaceholder` → 真 `ThermalController`（输出约束参与求交）。
