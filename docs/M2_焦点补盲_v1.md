# M2 焦点补盲 — 双扳机 Collector 与 systemui 盲区消除（v0.2.0）

> UnifiedRootOptimizer M2 · 2026-10-07 · 实现 + 四场景实测全过
> 消除对象：M1 影子对账 v2 §2-A 的 30 条 missed（systemui 盲区链，占 missed 总量 77%）

## 1. 问题回顾

`inotify /dev/cpuset/top-app/cgroup.procs` 是前台检测的最佳实践，但有原理性盲区：**systemui 常驻 top-app cgroup**，下拉通知栏/锁屏期间 cgroup 成员无任何变化 → inotify 永不触发。影响是链式的——不但吞掉 `systemui` 自身那条（22），还吞掉"收起后回到原 App"的恢复事件（8），因为整个过程 cgroup 从未动过。

## 2. 方案：第二扳机 `focus_driver`

| 项 | 决定 | 依据 |
|----|------|------|
| 信号源 | `dumpsys window` 取 `mCurrentFocus` | 焦点窗口与 systemui 状态强相关；独立于 cgroup |
| 巡检间隔 | **1s**（`DriverPaths::focusPollMs`） | 单次实测 **14–20ms**（对比 `dumpsys activity` 300–1000ms），2% 单核占空可进常驻 |
| 去重 | **`FgShared` 共享前台状态**，`publish()` 原子判重 | 与 inotify 扳机共享 last-known，谁先到谁发，天然防双发 |
| 语义 | 只在**包名**变化时发事件 | 同包内 Activity 切换（微信内跳页）不算前台变化，与 inotify 语义一致 |
| 模式 | SHADOW 只读 | 不写任何系统节点 |

### 焦点值 → 包名提取规则（`pkg_from_focus`）

实测焦点取值分布（run4 真值 B 的 194 条，45 种不同值）逼出的规则：

| 焦点值形态 | 处理 | 理由 |
|-----------|------|------|
| `Window{hash u0 com.pkg/com.act}` | 取 `/` 前包名 | 常态（42/45 种） |
| `io.github.mangi.eta`（无斜杠） | 原样 | 单任务态 |
| `NotificationShade` / `StatusBar` / `NavigationBar` / `Keyguard` | → `com.android.systemui` | 无点窗口名，归一为真值同款包名 |
| `mCurrentFocus=null` | **忽略，保持 last** | 锁屏过渡态，无包名可报 |
| `Pop-Up Window` / `弹出式窗口` / `PopupWindow:xxx` / `ActionsDialog` | **忽略，保持 last** | 系统弹窗只给窗口标题，强行解析必错；且 ResumedActivity 语义下弹窗不改前台 |

原则：**宁可漏一个周期，不发错误包名**——漏的下一周期自愈，错的会污染状态机。

## 7. 遗留清账：Keyguard 锁屏验证 + 双扳机仲裁（v0.2.1）

### 7.1 验证中暴露的缺陷

锁屏测试（POWER → 观察 → 解锁）显示焦点是 `NotificationShade`（非 Keyguard），映射生效。但**同一秒内两扳机打架**：

```
修复前 v0.2.0:
19:40:25 fg-focus   com.android.systemui   ← focus 说锁屏了（与真值一致）
19:40:25 fg-inotify io.github.mangi.eta    ← inotify 读 ResumedActivity，锁屏时它
                                             仍是底层 App，把状态拉回 → 真值没有这条
```

后果链与 M1 的 A2 模式同构：状态被拉回 eta 后，解锁时 `publish(eta)` 判重不发 → **恢复事件丢失**（对账实证 19:46:41 真值 eta missed）。若锁屏期间 cgroup 反复波动，还会 systemui/eta 交替震荡。

### 7.2 仲裁规则（v0.2.1）

`fg_driver` 触发后先读一眼焦点，若 `focus_is_non_app(raw)` 为真则**本次跳过**，锁屏语义交 focus 驱动主导：

| 焦点值 | 判定 | 依据 |
|--------|------|------|
| `NotificationShade`/`StatusBar`/`NavigationBar`/`Keyguard` | 非 App → 抑制 | 系统 UI 窗口，ResumedActivity 会给出矛盾答案 |
| `null` / `PopupWindow` / `Pop-Up Window` / `ActionsDialog` | 非 App → 抑制 | 无包名，强行解析必错 |
| 读不到焦点（空） | **放行** | 保守：不因采集失败而丢正常事件 |
| 正常 `pkg/act` | 放行 | 走原 ResumedActivity 路径 |

两个方向都自洽：锁屏时被抑制（focus 主导报 systemui），解锁时焦点已回 App → 照常走 ResumedActivity 发恢复事件。

**首轮实现踩坑**：判据写成"解析不出包名才抑制"，而 `pkg_from_focus(NotificationShade)` 返回的是 `systemui`（**非空**）→ 条件永不命中、编译通过但逻辑无效。正确判据是"焦点是否属于非 App 态"，与"能否解析出包名"不是一回事。
