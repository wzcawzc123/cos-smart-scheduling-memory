### 错误分类（全部定位到病根）

1. **解析语义错（spurious 8 + pkg 错 31 的主因）**
   resolver 用"top-app 内 pid 最大者"——微信 `:appbrand1`/`:xweb` 子进程、键盘 `baidu.input`、`permissioncontroller` 被误报为前台；真值报的是基包与真实 Resumed Activity。
2. **结构性盲区（missed 5 例 systemui）**
   systemui **常驻** top-app cgroup，成为前台时无成员变化 → inotify 永不触发。cgroup 触发方案的原理性盲区，需焦点类信号补充（挂 M2）。
3. **防抖坍缩（missed 其余 6 例）**
   500ms 窗内 2~3 连切只发最后一次（max 1.8s 即此案例）。

## 3. 修复决定（M1 内完成）

| 项 | 方案 |
|----|------|
| resolver v2 | inotify 仍作扳机；触发后 `dumpsys activity activities` 解析 **ResumedActivity**（与真值同源语义），25 次/h 频率下 fork 成本可忽略 |
| 防抖 | 500ms → 300ms（Δt 预期 avg ≤0.4s） |
| systemui 盲区 | 记已知缺口；M2 引入窗口焦点触发（`dumpsys window mCurrentFocus` 低频巡检或 uevent）补盲 |
| bootstrap 缺口 | 启动即读 mode.txt + ResumedActivity 一次（消除 `(unknown)` 初态） |
