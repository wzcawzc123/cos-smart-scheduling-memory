## 2. 关键障碍与解法：x86_64 宿主工具 × ARM64 宿主机

**问题**：NDK 只提供 linux-x86_64 宿主工具链，宿主机是 aarch64 → `clang++: Exec format error`（与当年 AGP aapt2 的问题同源）。

**解法（本次打通的配方）**：qemu-user + binfmt_misc 内核级透明转译，**一条命令内完成挂载+注册**：

```sh
mount -t binfmt_misc none /proc/sys/fs/binfmt_misc
printf '%s\n' ':qemu-x86_64:M::\x7fELF\x02\x01\x01\x00\x00\x00\x00\x00\x00\x00\x00\x00\x02\x00\x3e\x00:\xff\xff\xff\xff\xff\xff\xff\x00\xff\xff\xff\xff\xff\xff\xff\xff\xfe\xff\xff\xff:/usr/bin/qemu-x86_64-static:POCF' \
  > /proc/sys/fs/binfmt_misc/register
```

要点：
- mask 第 12 字节 `0xfe` 同时覆盖 ET_EXEC 与 ET_DYN（PIE）
- **binfmt 的 mount 是会话级的**（每个 shell 独立 mount namespace）→ 挂载、注册、构建必须在**同一会话**内完成；已存活的构建进程会持有其 namespace 存活
- 依赖已装包：`qemu-user` / `qemu-user-static` / `qemu-user-binfmt`（binfmt 注册需在挂载后手动补，包安装时 binfmt 尚未挂载会丢）

## 3. 构建命令（CI 等价）

```sh
export ANDROID_NDK=/workspace/android-sdk/ndk/26.3.11579264
export BUILD_TYPE=Release
./build.sh arm64-v8a     # 内部: cmake -DCMAKE_TOOLCHAIN_FILE=.../android.toolchain.cmake -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-29 -GNinja + cmake --build
```

编译在 qemu 转译下完成（clang 17.0.2），LLVM LTO 链接 + llvm-strip 由 ld.lld（qemu）执行。

## 5. 过程记录（如实）

- NDK 首次经 async 后台拉取被回收（215MB 处 SIGKILL），改 `daemon_start` 后约 2 分钟完成
- 构建在独立会话以 nohup 启动；链接完成，但 build.sh 末尾的 `cp` 在会话回收窗口内未执行 → **已手动补完 output/ 阶段步骤**（产物即 build/bin 下同一文件，md5 一致）
- 未做**运行时验证**（有意为之）：该二进制 `main()` 即构造调度器并直写 sysfs，M0 只验构建链；运行测试归 M2 dry-run 阶段，届时按 dry-run 协议在设备上执行

## 7. 可复用教训

1. **凡 x86_64 宿主工具链撞 aarch64 宿主机 → qemu binfmt 三步（mount + printf 注册 + 立即使用）**，同一会话内完成；这是 aapt2-qemu 案的通用化
2. async 后台任务会被轮间回收（本次 NDK 下载再验证）→ 长任务一律 `daemon_start` 或同会话 nohup
3. build.sh 的收尾步骤（cp/output）也是任务的一部分，中断后要人工核对是否完成，不能默认成功
