### 2.2 重大发现：系统存在第三写入方

两次探测间隔内 `scaling_min/max_freq` 被系统动态改写：

| 时间 | policy0 min/max | policy3 max |
|------|-----------------|-------------|
| 第 1 轮 | 556800 / 1785600 | 2803200 |
| 第 2 轮（约 1h 后） | 1017600 / 2016000 | **2054400**（低于 HW max） |

**Oplus 框架自身在动态钳制频率**（场景/温控/帧感知）。含义：
- baseline 不是静态值，快照必须带时间戳与来源标注；
- 我们写 scaling_max 后可能被系统覆盖 → Policy 需要"**readback + 按需重申**"（低频、事件驱动，仍遵守写完即走）；
- Constraint Engine 的 `kernelSupportedMax` 应取 `cpuinfo_max_freq`（硬件能力），而非 `scaling_max_freq`（当前状态）。

governor 切换：conservative / walt 均可用 ✅，但按 §3.4 铁律，默认保持 uag 不切换。

## 9. 总判定

| 类别 | 结果 |
|------|------|
| 上游 conf 四档 governor | ✅ 全部存在，但**默认保持 uag 不切换** |
| 上游 conf 频率值（12） | 6 ✅ / **6 需吸附改写** |
| 上游 ParamSchedPath（9） | 3 需改路径（→uag/）/ **6 缺失** |
| 上游 EAS sysctl（4） | 1 ✅（现值待决策）/ **3 缺失** |
| 上游 cpuset（5） | 2 ✅ / 3 需改（含收紧风险项） |
| GPU | ✅ 可用（路径必须 devfreq 动态探测） |
| PSI / thermal / 电源 | ✅ 观测面完备（T-OBS 就绪） |
| 第三方写入方 | **发现 Oplus 动态钳制 scaling_max/min——Constraint/重申机制必要性实证** |

**一句话**：上游参数表直接刷上去约三成会静默失效；能力矩阵 + 吸附改写 + 路径映射是 Adapter 的硬需求。观测面（PSI/thermal/前台通路）全绿，M1/M3 所需的地基已在。
