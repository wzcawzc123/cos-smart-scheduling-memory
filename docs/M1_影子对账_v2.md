## 4. 方法论教训（账本 #10/#11/#12）

10. **对账匹配必须对称时间窗 + 单调顺序配对**：首轮用单向窗 `(0,+win]`，同秒事件被判 missed+spurious 各一条、快速序列交叉错配——数字毫无意义。修算法后 5/13 → 9/13、spurious 4 → 0，代码未动一行。
11. **真值要双源交叉**：UserAwareMgr 与 mCurrentFocus 独立采集，两条 C 类"孤立漏检"靠双源对照 5 分钟内定位为盲区下游；单源永远查不出"真值本身漏了"。
12. **盲区的影响是链式的**：A1（systemui 本身）会派生 A2（恢复事件），按"单点盲区"估算会严重低估缺口规模（22 vs 实际 30）。分类时不能只看漏检事件本身，要回溯其前置序列。
