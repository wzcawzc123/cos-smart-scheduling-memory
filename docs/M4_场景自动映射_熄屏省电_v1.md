# 场景自动映射：熄屏省电 / 亮屏回均衡（v0.10.0）

> 2026-10-08 · 用户诉求原话："亮屏日用=均衡、熄屏=省电，这个没实现吗？"——**此前确实没有**

## 1. 改动

**`pick_scenario` 新分支**（优先级顺序）：

```
1. GAME        仅 st.screenOn 时成立（熄屏时"在玩游戏"无意义，交省电接管；
                挂机游戏进程安全：reclaim 不杀前台、freeze 只冻后台）
2. 熄屏        !screenOn → POWERSAVE（复用整套省电策略：回收+冻结+maxKill3+uag 2500）
              ↑ 亮屏后自然回落 DAILY（屏幕是清晰边沿，无需滞回）
3. MEMORY_PRESSURE（15s 滞回不变）
4. mode=powersave
5. DAILY
```

## 2. 真机根因（一个隐藏 bug）

`screen_driver` 用 `debug.tracing.screen_state` 判亮灭，原判定 `raw==0` 为灭。
**实测 Oplus 语义：亮屏=2、熄屏=1** → 熄屏值被误判为"亮着"，`ScreenChanged(off)` 永不触发。
改判 `raw==2` 为亮。StateManager 的事件→screenOn 链路本来正确，坏的只有这一处判定。

## 3. 真机验收（telemetry 留痕）

```
12:23:41 熄屏 → gen3 POWERSAVE why:"screen off -> powersave" maxKill=3 uagUpRate=2500
12:23:47 亮屏 → gen4 DAILY     why:"mode=balance"            maxKill=0 uagUpRate=-1(回基线)
```

## 4. 测试

单测 124 全过；m3 新增 `screen-auto` 3 断言（熄屏省电 / 熄屏压过 GAME / 亮屏 GAME 照常）。
途中修：`Event{type, "off"}` 聚合初始化参数错（Event 是 5 字段结构）→ 改字段赋值。

## 5. 场景全景（当前生效的完整映射）

| 场景 | 触发 | 动作 |
|---|---|---|
| 熄屏 | screenOn=false | 省电策略 |
| 亮屏日用 | 默认 | DAILY：**什么都不做**（基线） |
| 游戏 | 亮屏+前台名单 | 全量让权 |
| 压力 | PSI≥5 或 Mem<1G | 彻底清理（15s 滞回） |
| 省电模式 | 你手动切 mode | 省电策略（与熄屏同款） |
