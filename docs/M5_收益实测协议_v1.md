# M5 收益实测协议 v1.0（URO 收益拿数据）

> UnifiedRootOptimizer E 阶段 · 2026-10-08 起 · 对齐 M0 基线方法
> 前置：v0.17.0 已部署，Evidence 自动采集 60s（thermal.jsonl 含电量、fps.jsonl、telemetry）

## 1. 三方对照设计

| 段 | 条件 | 时长 | 操作 |
|---|---|---|---|
| A（进行中） | **enforce=ON**（现态，四档自治） | ≥2h 日常 + 过夜待机 | 正常使用即可 |
| B | **enforce=OFF**（总闸关=完全基线） | 对等时长（日常+待机夜） | 看板/面板「统一调度桥接开关」一键关，测完开回 |
| C（已有） | M0 基线 | 日常 117min/468帧；待机 6.09h 耗 3.0% | 已归档 docs |

- 切换时机：**连续对等场景**（例如两个工作日晚、两个过夜）；间隔期正常用不记数据
- **B 段注意**：总闸 OFF 只停 URO 写入（桥/进程仍跑、Evidence 仍在采）——测的是"URO 干预"的收益；若要"URO 进程本身开销"另设 C′（模块 disable 重启），非本协议范围

## 2. 指标与数据源（全部自动，60s 粒度）

| 指标 | 源 | 算法 |
|---|---|---|
| 电量消耗 %/h | thermal.jsonl `pct` | 只取 `chg=Discharging` 连续段差分 ÷ 小时；充电段剔除 |
| 电池温度均值/峰 | thermal.jsonl `battery` | 段内均值 + max |
| CPU 热点温度 | thermal.jsonl `top[0].c` | 段内均值 + max |
| 帧率/jank 率 | fps.jsonl `frames/janky` | Σframes/Σ时间、Σjanky/Σframes；`reset` 行不计 |
| 档位行为审计 | telemetry.jsonl | 段内各档时长、applied 写入次数 |
| 对齐 M0 口径 | 同上 | 日常段折算"每小时帧数"与 468帧/117min 对照 |

## 3. 场景控制（诚实标注非受控项）

- 自然使用不可复现：**记录段内主观场景**（通勤/室内/游戏时长粗标），偏差如实入报告
- 待机段口径：熄屏、不充电、后台保留——与 M0 的 6.09h/3.0% 对齐
- 游戏/App 画像规则在 A/B 段保持不变（app_profiles.txt、game_apps.txt 冻结）

## 4. 判读标准

- **有效收益**：A 段 %/h 显著低于 B 段（>10% 相对差）且均温不升；或同帧产出 jank 率降
- **无收益/负收益**：如实报告（参数效果属设计意图，M5 是第一次拿数据——不预设结论）
- 样本量不足（<2h 或单段）→ 只出观察、不出结论
