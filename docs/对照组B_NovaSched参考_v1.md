# 对照组 B：NovaSched Zen Edition 参考方案（映射到 SM8550）

> 目的：把同类项目（NovaSched）的真机调优结果映射到本机（一加11 / SM8550），
> 作为 A/B 实验中的**对照组 B**（"别人同款"）。
> 来源：`zeng060812-creator/NovaSched-Zen-Edition`（作者 **ZenJooo**，GPL-3.0），
> 依据其 `README.md` 与 `docs/fix-v2.8.0.md`（2026-10，versionCode 380）。
> 归因：本文件仅为方法论与数值的**参考记录**，不复制其代码；数值经我们重新映射到本机频点表。

## 1. 它的做法（方法论）

1. **取真机 OPP 频率表**（`adb` 采集 `scaling_available_frequencies`）
2. 四档按**每簇百分比**设上限：省电 / 均衡 / 性能 / 极速
3. 百分比**向下吸附到最近的真实频点**（不写不存在的频率）
4. 只用真机数据调优：SM8650（小米 14）逐频点适配；其余 9 款处理器用"均衡=省电+6pp"的通用百分比

## 2. 它的四档（SM8650 实测，四簇 1+3+2+2）

| 档位 | 模板百分比（小/中3/大2/超大） | 实际频点 MHz | 定位 |
|---|---|---|---|
| 省电 | 65 / 52 / 51 / 56% | 1459 / 1613 / 1498 / 1824 | 日用低功耗 |
| 均衡 | 80 / 68 / 69 / 69% | 1805 / 2131 / 2035 / 2246 | 日用甜点 |
| 性能 | 85 / 84 / 85 / 82% | 1920 / 2630 / 2496 / 2688 | 王者 120 帧甜点，保留 8% 底频 |
| 极速 | 95 / 100 / 100 / 100% | 2150 / 3149 / 2957 / 3302 | 游戏专用（原神/鸣潮全频段） |

**它自己的关键教训（值得抄）**：
- 旧省电档把小核压到 1178 MHz → HyperOS 下信息流/通知动画**就是会卡**；
  新省电把小核放宽到 1459 MHz → "低功耗且不卡"。
- 极速档**只做游戏**，档位说明直接写"游戏专用，日用选均衡"。

## 3. 映射到本机（SM8550 / 一加11，三簇 1+2+2+3）

本机频点表（实测）：

| 簇 | CPU | 频点数 | 范围 | cpuinfo_max |
|---|---|---|---|---|
| policy0（小核 A510 ×3） | 0-2 | 16 | 307.2M ~ 2016.0M | 2016000 |
| policy3（中核 A715×2+A710×2） | 3-6 | 19 | 499.2M ~ 2707.2M | 2803200 |
| policy7（大核 X3 ×1） | 7 | 20 | 595.2M ~ 2956.8M | 3187200 |

按 NovaSched 百分比 **向下吸附**到本机频点：

| 档位 | policy0 目标(kHz) | 吸附后 | policy3 目标 | 吸附后 | policy7 目标 | 吸附后 |
|---|---|---|---|---|---|---|
| 省电 | 1310400 | **1228800** | 1457664 | **1401600** | 1784832 | **1708800** |
| 均衡 | 1612800 | **1555200** | 1906176 | **1785600** | 2199168 | **2092800** |
| 性能 | 1713600 | **1670400** | 2354688 | **2323200** | 2613504 | **2592000** |
| 极速 | 1915200 | **1900800** | 2803200（cap） | **2707200** | 3187200（cap） | **2956800** |

> 说明：百分比取"该簇与 SM8650 对应簇"的值——小核↔小核、中核(4核)↔中核(3核)、
> 大核(X3 单核)↔超大核(X4)。这是跨平台映射的**近似**，正因如此它才需要 A/B 验证。

## 4. 与本机的路线差异（关键冲突点）

| 维度 | NovaSched | 我们 |
|---|---|---|
| 调速器 | **骁龙全系 `walt`**（性能/极速档；省电/均衡留原厂） | **不换**（实测 uag 吞吐持平且更省；换 walt 只增功耗） |
| 频率控制 | 直接写每簇 `scaling_max_freq`（百分比化） | 已通（v0.33 起可配置），**目前只落 policy0** |
| 帧感知 | **NovaFAS**（按前台帧信号动态调频） | ❌ 缺（第 5 批待办） |
| uclamp / 输入加速 | 有 | 未接 |
| 让权语义 | 无（始终接管） | ✅ GAME 全量让权 + 安全阀 |
| 审计/回滚 | 原厂快照恢复 | ✅ 2PC + 基线归还 + telemetry |

**结论：这组差异正好构成一组干净的 A/B 对照**——特别是"walt vs uag""单簇 vs 三簇"两点。

## 5. 落地前提（当前代码缺口）

对照组 B 需要**每簇独立上限**，而当前 `CpuController` 的夹频只写 `policy0`：

```
缺：per-cluster clamp（policy0 / policy3 / policy7 各自的上限）
```

补齐后，本文件第 3 节的表格即可直接写成 `uro_tactics.conf` 的对照组配置（每个档位三行）。
