## 2. 三模式到底改了什么（核心结论）

### 2.1 全程零触碰的资源（66 帧快照 diff 计数）

| 资源 | 变化次数 | 结论 |
|------|----------|------|
| cpuset 八组 | 0（唯一 1 次是采样被终止的残缺行） | **游戏助手不碰 cpuset** |
| uclamp（top/fg/bg） | 0 | 不碰 |
| uag 调速参数（hispeed/target_loads/soft_limit） | 0 | 不碰 |
| 核心在线 cpu0-7/online | 0 | 不碰 |
| governor | 0（全程 uag） | **不切换 governor** |
| GPU devfreq min/max/governor | 0（仅 cur_freq 随 msm-adreno-tz 自己动） | 不碰上下限 |
| sched sysctl（util_clamp/energy_aware） | 0 | 不碰 |
| settings 键 | 仅 `debug_gamemode_value`、`disturb_for_game_space_mode_flag` | **无性能模式持久化键** |

### 2.2 唯一的战场：`scaling_min_freq` / `scaling_max_freq`

- 模式切换表现为**瞬态 min=max 锁频脉冲**（锁十几秒后释放），非常态驻留改写
- 同时 **Oplus 框架自身以 ~6s 粒度持续钳制 scaling_min/max**（session 内 P3/P7 limit 变化 44~57 次）——这与能力矩阵 §2.2 发现一致
- perf HAL 层未见模式相关 perf_lock（仅音频 AutoPerfLock + 一次 SELinux 拒绝的 IPerf 查询），模式切换走框架内通道，日志级别低

### 2.3 对 Handover 设计的裁定

1. **三方争用资源 = 仅频率上下限**（Oplus 动态钳制 + 游戏助手脉冲 + 本框架）——Handover 的核心动作就是**游戏场景撤出 scaling_min/max 写入**，其余（cpuset/uclamp/uag/GPU/online）经实测与游戏助手**无争用**
2. 游戏助手不切 governor → 我们"保持 uag 不切换"默认正确
3. 进/出游戏各有明确事件（GameMode=1/0 + topAppChanged）→ Handover 触发器可靠，且**进游戏脉冲（02:06:51）先于我们响应也无害**（因为我们是撤出不是写入）
4. 普通 App 冷启同样有拉频脉冲（02:10:27）→ LaunchBoost 与系统自带 boost 也会重叠，LaunchBoost TTL 设计必须按"允许短暂重叠、到期即撤"处理

## 4. 温控移除模块（Extreme GT）对本次数据的影响评估

**模块**：`extreme_gt`（SCENE ExtremeGT）——`service.sh` 对 shell*/batt/usb/wlan/xo 及指定 SoC 热区写 `emul_temp` 固定值（shell_t=33000、其余 29500），描述为"去除锁帧和部分温控限制"。

| 数据面 | 影响 | 判定 |
|--------|------|------|
| **温度读数** | `shell*` 全程恒 33000 = 模块伪造值实锤（与脚本 shell_t 完全一致）；batt/wlan/xo 等同理被固定 | **本 session 的 shell/电池类温度数据作废**；zone0 `pa`（45~47°C）不在伪造名单，仍为真实值 |
| **频率/模式指纹** | 温控钳制被移除 → 频率行为只反映"模式 + 负载"，**去掉了热降频这个混淆变量** | ✅ **反而更干净**，指纹有效 |
| **基线测量**（M0 待办） | 本 session 的频率动态**不能代表**正常温控下的行为 | 基线测量必须记录该模块状态（禁用测一轮 或 带状态标注测一轮） |
| 锁帧 | 模块同时移除锁帧 → 帧率/刷新率观测同样带条件 | 同上，记为条件变量 |

**回答你的问题：对"游戏助手指纹"没影响，反而帮忙；对"温度数据"有影响（shell/batt 是假的）；对后续"基线测量"要当条件变量记录。**

## 5. 采样方法缺陷记录（下轮改进）

1. 前台采样取 `top-app/cgroup.procs` 前 4 个 pid，**没抓到游戏进程**（顺序不稳定）→ 改为全量 pid + cmdline，或直接用 `handleTopAppChanged` logcat 锚定（本次靠 logcat 补救成功）
2. 5s 间隔对"十几秒的瞬态 pin"够用，但**模式点击无独立日志**，档位对应只能推断 → 下轮若需确凿：一次只切一个模式 + 1s 采样
3. `pkill -f` 模式串自伤（匹配到自身 shell）→ 改为按 pid 文件 kill（已修正）
